GopherCon 2026もいよいよ最終日です。今日も朝からFinneran Ballroomでシングルトラックのトークが続き、暗号からコンパイラ、巨大モノレポの運用まで幅広いテーマが揃った一日でした。

# The Go Cryptography State of the Union（Filippo Valsorda / Geomys）

Goの暗号ライブラリのメンテナーであるFilippoさんによる、毎年恒例の「今年のGo暗号事情」です。暗号の世界はいまキャリアの中でも類を見ない速さで変化していますが、アプリケーション側の破壊を最小限に抑えながら安全性を保つ、というGoらしいスタンスが貫かれていました。

トピックは盛りだくさんでした。

- 新しいML-DSAパッケージとそのテスト手法
- ポスト量子暗号への移行準備
- 新しいHPKEパッケージ
- 乱数とエントロピーの話
- `runtime/secret`によるエフェメラルな秘密情報の確実な消去
- `crypto/tls`で対応することになった、繊細で複雑なセキュリティ問題の裏話

# What slog Left on the Table（Dylan Bourque / CoreWeave）

Go 1.21で標準ライブラリ入りした`log/slog`は基本を押さえている一方で、大規模な実運用では痛みになるギャップが残っている、という話です。`slog.Handler`インターフェースの上に作った二つの拡張が紹介されました。

一つ目は`testing.T`と統合するカスタムハンドラーで、ログをテストの出力にルーティングすることで、成功したテストではログのノイズを抑えつつ、失敗したテストでは本番相当のフルログを表示してくれます。ハンドラーの実装だけでなく、ハマりどころのエッジケースの解説もありました。

二つ目はコンポーネント単位で動的にログレベルを変えられる仕組みです。再起動なし・パフォーマンスペナルティなしで、特定のサブシステムだけDEBUGにできるというもので、「DEBUGを有効にしたらログの雪崩で肝心のログが埋もれた」経験のある人には刺さる内容でした。

# Parsing Protobuf as Fast as Possible（Sunny Young de la Sota / Buf Technologies）

Buf社の[hyperpb](https://github.com/bufbuild/hyperpb-go)という、あらゆる高速化テクニックを注ぎ込んだGo向けProtobufパーサーの話です。テーブル駆動パーシングというパーサーのパラダイムと、その上に積んだhyperpb独自の工夫、そしてコンパイラ・パーサーVM・レイアウト最適化といった全体アーキテクチャが解説されました。Advanced枠だけあって内容は濃かったですが、パフォーマンスチューニングの引き出しが増えるトークでした。

# From Go to Factorio: What Games Can Teach Us About Compilers（Simon Li / Meta）

Goコンパイラがプログラムを変換していく途中経過という「普段誰も見ない隠れたレイヤー」を、ゲームのFactorioの工場として可視化して遊んでしまおうという話です。「The factory must grow.」の一文で会場のFactorioプレイヤーは全員ニヤリとしていました。コンパイラの中間表現をここまで楽しく見せる発想はなかなかないと思います。

# Sandboxing DuckDB with io/fs（Achille Roussel / Firetiger）

Cライブラリを組み込んだGoプログラムには「Cライブラリが自前のI/Oスタックを持ち込んでくる」という隠れた罠があります。Cライブラリ側はGoの認証情報もTLS設定もリクエストトレーシングもリトライロジックも知らないので、同じバイナリの中に二つのI/Oシステムが並走してしまうという問題提起から始まりました。

題材は組み込みデータベースのDuckDBです。httpfsやawsといった拡張はC++から直接ネットワークI/Oを行うため、Goでラップするとオブザーバビリティもクレデンシャル管理も失われてしまいます。解決策として、Go 1.16で入った`io/fs`インターフェースとDuckDBの仮想ファイルシステムAPIを小さなC++拡張でブリッジし、ライブラリのI/OをすべてGoランタイム経由に戻すパターンが紹介されました。このパターンは他のCライブラリにも応用でき、DuckDB向けにはこれを実装したOSSライブラリも公開されているそうです。

# Receipts from the Go Linker: Auditing the Cost of Dependencies（Mikayla Toffler / Datadog）

「すべてのimport文はトランザクションなのに、私たちはレシートを確認しない」という掴みが秀逸なトークでした。go.modからコンパイル後のシンボルまで依存を追いかけて、Goリンカーが実際に何をバイナリに取り込むのか、デッドコード除去（DCE）がどこで効いてどこで失敗するのかを解説してくれました。バイナリサイズを密かに膨らませるパターンの紹介もあり、ライブラリメンテナーにもプロダクトエンジニアにも役立つ、依存を評価するためのツールキットが持ち帰れる内容でした。

# Lightning Talks

昼食後は今日もライトニングトークが6本連続で行われました。

**Perform Inference Directly in Your Go Applications with Kronk（Bill Kennedy / Ardan Labs）**
GoコミュニティではおなじみのBillさんによる、セルフホスト推論の話です。CGoもPythonもOllamaへのネットワークホップもなしに、Kronkを使ってGoアプリケーションの中で直接モデル推論を行うデモでした。Qwen3.5-0.8B-Q8_0のような小さいモデルなら普段使いのラップトップで十分動くそうで、トークン課金なし・データが外に出ない・ベンダーロックインなしというセルフホストの利点が強調されました。

**A Small Update About TinyGo（Ron Evans / The Hybrid Group）**
「最小の場所のためのGoコンパイラ」TinyGoの最新情報です。

**Creating a full desktop environment with Go!（Andrew Williams / Apptrix.ai）**
デスクトップ環境そのものを丸ごとGoで書いてしまったという話です。コードスニペットとスクリーンショットを織り交ぜた駆け足のツアーで、最後は「試して、コントリビュートしてね」という呼びかけとサプライズの発表で締めくくられました。

**Nip the Nits in the Bud（Garrett Denis / Skool）**
コードレビューで繰り返される「nit」コメント（改行位置やスタイルの好みなど）は、レビュアーの注意を正しさや設計から奪ってしまいます。実際のコードベースにあった「boolean条件は1行1節」というnitを題材に、`go/analysis`で自動修正付きのカスタムリンターを作ってgolangci-lintに統合するまでを一つの実例で見せてくれました。「客観的で繰り返し登場するスタイルの決めごとは、レビュースレッドではなくツールに属する」というメッセージは、AIがコードを量産する時代にますます重要になりそうです。

**AI is a Power-up, Not a Player（Seth Lumnah / Capital One）**
大きな組織で共有Goライブラリをメンテナンスする立場から、「ボトルネックはコードではなく注意力（attention）」という洞察を軸に、スタイルガイドをAIに参照させて定型作業を任せるエージェントスキル（Markdownファイル）の実例を紹介してくれました。タイトルの「AIはパワーアップアイテムであってプレイヤーではない」が全てを物語っています。

**Safer Agent Infrastructure: Don't Give the Agent Your Keys!（Marc Dougherty / Google, Go Team）**
今のAIエージェントはユーザーの認証情報をそのまま使うデスクトップソフトウェアであり、それがトークン漏洩やニュース沙汰の想定外の挙動につながっている、という問題意識の話です。エージェントに鍵を渡さないための認証と委譲クレデンシャル管理の戦術が紹介されました。

# Uber-Scale Changes: Managing Millions of Lines of Go（Sung Whang / Uber）

UberのGoモノレポは1億行に達していて、数千人のGopherが今も書き続けているそうです。そんなコードベースで数万ファイルにまたがる「Uberスケールの変更」をどう実施するかという話で、AST変換ツールとAIによる自動化の仕組みが紹介されました。規模の桁が違いすぎて笑ってしまいましたが、大規模リファクタリングの考え方自体はどの組織でも参考になると思います。

# Detect, Trace, Fix: Bringing AI-Powered Taint Analysis to gosec（Ravi Sastry Kadali / General Motors）

セキュリティ解析ツールのgosecに、AI対応のテイント解析エンジンを持ち込む話です。信頼できないデータがアプリケーション全体をどう流れるかを追跡することで、SQLインジェクション、コマンドインジェクション、パストラバーサル、SSRF、XSSなどを正確に検出します。SSAとコールグラフに基づく解析がGoにおけるデータフロー追跡を実用的にし、偽陽性を大きく減らすこと、そして同じアーキテクチャがAIによる自動修正の基盤になることが解説されました。「検出する」から「追跡し、理解し、修正する」へというGoセキュリティツーリングの方向性を感じるトークでした。

# Automation Tools for Large-Scale Go Code Transformations（Ian Alexander / Google, Go Team）

Goチーム自身も大規模なコード変換に取り組んでいます。goコマンドのモジュールローダーやGoコンパイラの内部構造のリファクタリングを題材に、複雑なマージコンフリクトの解消や、時間のかかる大規模変更（LSC）をプログラマティックな変換で乗り切るテクニックが紹介されました。Uberのトークと合わせて聴くと、大規模コード変換が一つの分野として確立しつつあるのを感じます。

# Chasing the Moon: Engineering a High-Performance Lua VM in Pure Go（Salah Mahmud / Palliser Analytics）

NeovimやRedis、Nginxなどで使われている組み込みスクリプト言語Luaを、Pure Goで高速に実装した話です。C実装のPUC LuaをGoに組み込むとCGoのビルドの複雑さと呼び出しオーバーヘッドが付いてきますが、既存のPure Go実装は2〜3倍遅くメモリも食う、というのが従来の状況でした。新しいレジスタベースのVMはCGoフリーのままPUC Luaの30〜50%以内の性能を達成したそうです。

トークの主眼はVMの内部というより、これを題材にした高性能Goプログラミングの技法にありました。メモリレイアウトの最適化、GC圧の削減、隠れたアロケーションの排除、キャッシュフレンドリーなデータ構造の構築など、インタープリタ以外にも応用できる話が多く、ベンチマーク・プロファイリング・エスケープ解析・インライン化診断を使った実践的な最適化ワークフローのデモもありました。

# Building a Durable Agent & MCP Execution Engine in Go（Samantha Kendziora / Diagrid）

AIエージェントのフレームワークのほとんどはdurable（耐久的）ではなく、ツール呼び出しの途中でプロセスが落ちると実行もコンテキストも失われてゼロからやり直しになります。さらにMCPではelicitation（ユーザーへの入力要求）やsampling（LLM補完のトリガー）でツール呼び出しが数分単位で中断・再開されうるため、単純なリトライループではモデル化できない、という問題設定です。

解決策として、決定的リプレイ、チェックポイントベースの再開、Virtual ActorパターンとGoのプリミティブによる耐久性エンジン、そして透過的な組み込みMCP durabilityワーカーという構成要素が解説されました。昨日のミツバチのトークに続いてDiagridの方で、ワークフローエンジン技術の応用範囲の広さを感じました。

# A Slice of Go's Future（Go Team パネル）

GopherCon 2026を締めくくる最後のセッションは、Goチームによるパネルディスカッションでした。テーマは初日のキーノートとも呼応する内容で、コミュニティからの質問に答える形で進みました。

- Goプロジェクトの長寿命化とコミュニティのニーズへの適応を支える、よりオープンでスケーラブルな技術ガバナンスモデル
- AIツールが業界に浸透する中で、言語の好みやエンジニアとしてのアイデンティティがどう変わっていくか
- 急速に進化するAIモデルとポスト量子暗号への懸念を踏まえたセキュリティの未来
